# Modernization workspace

This directory starts empty except for this contract. Agents create evidence and decisions here as a modernization progresses; do not pre-populate it with example results.

Expected generated structure is scoped by stable application ID:

```text
modernization/
  <application-id>/
    lifecycle.json     Machine-readable stage, status, revisions, approval, gaps, and handoff paths
    inventory/         Extraction manifests and reconciliation
    analysis/          Discovery index, context, dependencies, rules, data, interfaces, and risks
    architecture/      Target decisions, ADRs, contracts, threat model, and data mappings
    plans/
      <slice-id>/      Slice-plan index, plan, traceability, rollout, and rollback
    evidence/
      characterization/
      <slice-id>/
        <validation-run-id>/
                       Findings, gate report, parity, accessibility, security, and operations results
        deployments/
          <deployment-run-id>/
                       Terraform plan/apply evidence, approvals, connectivity, and rollback results
```

These artifacts are lifecycle checkpoints and agent handoffs. They remain versioned with the implementation because they record why code exists and what evidence supports it. They are generated by the Legacy Analyst, Modernization Planner, selected Java or Dotnet Implementation Agent, Azure Deployment Agent, and Validation Critic, not stored in another service automatically.

Copy canonical JSON indexes from `.github/templates/modernization/`. JSON contains stable identifiers, lifecycle state, revisions, and artifact paths; Markdown contains detailed evidence and reasoning. Before a handoff, run:

```powershell
python -B .github/scripts/validate_lifecycle.py `
  modernization/<application-id>/lifecycle.json `
  --transition <to-planning|to-implementation|to-validation|to-deployment-plan|to-deployment-apply|to-azure-validation|to-next-slice>
```

Only an accountable human or external approval process may set `approval.decision` to `approved`.

Do not put target application code, credentials, production records, or unmasked protected data here.
